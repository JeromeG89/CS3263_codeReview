# CS3263: Direct LLM review vs. LLM-to-Z3 translation for C safety invariants

CS3263 (NUS) project by **Jerome Goh** (lead), **Mothiki Eswara Anirudh** and **Goh Joon Xiang**.

**The question.** Can an LLM tell whether a C function can violate a safety invariant (array bounds, division by zero, signed overflow, invalid shift), given the preconditions its callers guarantee?

**The comparison.** We use the same model in two ways:
1. **Direct**: the LLM reads the code and answers `SAFE` / `UNSAFE`, with a concrete bad input for UNSAFE.
2. **LLM → Z3**: the LLM translates the question into a Z3 (Python) script, and *we* run the solver. `sat` means UNSAFE (the solver's model is the bad input); `unsat` means SAFE.

**Checking.** Every bad input claimed by any system is re-run on the real C code, compiled with clang's AddressSanitizer and UndefinedBehaviorSanitizer. That separates confirmed bugs from spurious ones.

**The benchmark.** 120 C functions in 60 minimal pairs (an UNSAFE function and a SAFE twin) over four difficulty tiers. Every label is validated by sanitizers, a reference Z3 encoding, CBMC and fuzzing.

## Setup

Python ≥ 3.10. Developed on macOS (Apple silicon).

```bash
# Python environment
uv venv
uv pip install -e ".[dev]"     # or: python -m venv .venv && .venv/bin/pip install -e ".[dev]"
source .venv/bin/activate

# C toolchain with sanitizers (Apple clang from the Command Line Tools works), and CBMC
xcode-select --install
brew install cbmc

# Local models (only needed to re-run the local experiments)
brew install ollama
ollama serve                   # in a separate terminal (or run the Ollama app)
ollama pull qwen2.5-coder:7b
ollama pull llama3.2:3b

# API keys
cp .env.example .env           # then put your GEMINI_API_KEY in .env
```

- **`.env` holds your secrets and is gitignored.** It is never committed. `.env.example` is the shared template showing which settings exist.
- The scripts add `src/` to `sys.path` themselves, so the editable install is a convenience, not a requirement.
- Set `CC` to use a compiler other than `clang`, and `OLLAMA_HOST` if Ollama does not run at `http://localhost:11434`.

## Running things

All commands are run from the repository root.

```bash
python -m pytest                                    # 144 tests, about 30 s (-m "not slow" for about 10 s)
python scripts/validate_dataset.py                  # check every label; exits non-zero on any disagreement
python scripts/run_baselines.py                     # reference Z3, CBMC, fuzzing
python scripts/run_eval.py --config configs/local.yaml
python scripts/run_eval.py --config configs/gemini.yaml
python scripts/rescore.py                           # after any change to parse.py / z3run.py
python scripts/analyze.py                           # tables + figures
python scripts/build_appendices.py                  # report/APPENDIX.md
python scripts/run_status.py                        # report/RUN_STATUS.md
```

**`run_eval.py` options:**
- `--config` (required).
- `--approaches A...` overrides the config.
- `--models SUBSTR...` is a substring filter on model names.
- `--only PREFIX...` takes instance-id prefixes (e.g. `T1 T2-BND`).
- `--workers N` and `--limit N`.

**Resuming.** `run_eval.py` is resumable. Every finished (model, approach, instance) is one line in `results/runs/<run>/records.jsonl` and is skipped on the next run.

**API failures.** Calls that fail at the API level (quota exceeded, network) are **never recorded**. They are retried on the next run, and the run stops after 5 consecutive failures. If a run stops, run `scripts/run_status.py`, commit the records file and `RUN_STATUS.md`, and a teammate can continue with their own key.

**Gemini notes:**
- Run `scripts/list_gemini_models.py --filter flash` first: Google retires model ids. The 2.5 models are refused for new users, which is why the config uses 3.5 Flash-Lite and 3.8 Flash.
- The client throttles to 10 requests/minute, and the free tier's daily quota resets at midnight Pacific time.
- `gemini-3.8-flash` runs with `thinking_budget: 0`. `gemini-3.5-flash-lite` rejects that option, so it runs with the API default.
- An ablation of an already-listed model (e.g. thinking on) must set `label_suffix`, or its records collide with the base model's.

## Dataset format (for adding instances)

Instances are multi-document YAML, with one document per instance separated by `---`. Full details and design rationale are in `report/IMPLEMENTATION.md` §5.

| field | meaning |
|---|---|
| `id` | `T<tier>-<BND\|DIV\|OVF\|SHF>-<nn>-<U\|S>` |
| `pair` | the shared id of the two twins (`T1-BND-01`) |
| `label` | `safe` or `unsafe` |
| `tier` | 1 straight-line · 2 branching · 3 loops · 4 helpers / nested loops |
| `category` | `bounds` · `div_zero` · `overflow` · `shift` |
| `twin` | `code`: the twins differ in code. `precondition`: the code is identical and only the preconditions differ |
| `tags`, `description`, `bug_explanation` | metadata for analysis. **Never shown to the models** |
| `entry` | the function under review |
| `params` | a list of `{name, type}`. `type` is `int`, `unsigned`, `long long`, or one of these with `[]` for an array. Arrays need `len`, either a literal or an expression over scalar parameters such as `n` or `n * (n + 1) / 2` |
| `requires` | C boolean expressions over scalar parameters (`&&`, `\|\|`, `!`, `INT_MAX`, `INT_MIN`, …), evaluated over mathematical integers |
| `elem_requires` | `{array: condition}`, which must hold for every element, with `_` as the element, e.g. `{a: "-1000 <= _ && _ <= 1000"}` |
| `witness` | required for `unsafe`: a concrete bad input such as `{buf: [7], n: 1, i: 0}` |
| `code` / `code_from` | the C source. A precondition twin may say `code_from: <id>` to reuse its partner's code |
| `reference_z3` | the gold Z3 script (protocol in `IMPLEMENTATION.md` §7) |
| `unwind` | the CBMC loop-unwinding bound (default 40) |

After adding instances, run `scripts/validate_dataset.py`. An instance is accepted only when the executed witness, the reference Z3 encoding, CBMC and fuzzing all agree with its label.

## Reproducibility

- **Deterministic settings.** Temperature 0 and a fixed seed for every model call. Fixed seeds for fuzzing. CBMC and the sanitizer harnesses are deterministic.
- **Response cache.** Every successful LLM response is cached in `results/cache/llm_cache.sqlite`. Re-running a configuration replays them without calling the model.
- **Stored answers.** All raw model answers are stored in the records files, so scoring can be redone (`rescore.py`) without new calls.
- **No label leakage.** Prompts never contain instance ids, labels, descriptions, witnesses or reference encodings, and a test enforces this.
